# Source ledger

Checked 2026-09-08. Exact bytes, query/resource URLs, retrieval times and SHA-256 hashes are saved in the local source archive and API receipts.

- City neighbourhood metadata: `https://ckan0.cf.opendata.inter.prod-toronto.ca/api/3/action/package_show?id=neighbourhoods`; select the exact `Neighbourhoods - 4326.geojson` resource. GeoJSON CRS84 axis order is longitude, latitude. Full-resolution source geometry is preserved; invalid or ambiguous CRS fails acquisition.
- Bike Share discovery was verified through the City's catalog. Its discovery JSON is an archived 2019 response. Only its operator URLs were used to locate current feeds, not its old statistics or timestamp.
- Operator station information: `https://tor.publicbikesystem.net/ube/gbfs/v1/en/station_information`.
- Operator station status: `https://tor.publicbikesystem.net/ube/gbfs/v1/en/station_status`. GBFS v1 fields are validated as observed; no v3 schema is assumed. Raw response and individual last_reported timestamps are distinct.
- City 3D massing metadata: `https://ckan0.cf.opendata.inter.prod-toronto.ca/api/3/action/package_show?id=3d-massing`. Exact 2025 archive URL, archive hash, validation accounting, geometry CRS and height field are in `docs/buildings-validation.json`. Metadata inside the source XLSX defines AVG_HEIGHT in metres. All qualifying height-source categories are preserved verbatim. No metadata category is silently treated as a survey.
- OpenStreetMap tiles: `https://tile.openstreetmap.org/{z}/{x}/{y}.png`; visible attribution, normal browser caching, no bulk download. [Usage policy](https://operations.osmfoundation.org/policies/tiles/). Context only.

The City portal displays Open Government Licence – Toronto while the CKAN records say `notspecified`; this discrepancy is exposed in the receipts. City Planning supplies the massing model for illustrative purposes with an additional accuracy/fitness notice. Do not infer suitability for legal, engineering or emergency decisions from source availability.

Raw fixture-free data and snapshots stay local. No private PDFs or existing project datasets were imported.

- Esri World Imagery: `https://services.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer`. Actual satellite/aerial mosaic used as display context. Capture dates vary and are not resolved per pixel; not live or a textured mesh. Provider credits are shown on the map.
- Optional Google Maps Photorealistic 3D Tiles: `https://tile.googleapis.com/v1/3dtiles/root.json`, requested only after explicit viewer activation with a locally configured restricted browser key. Cesium displays provider credits on-screen. No Google tile data enters the analytical store or models; account billing, authentication, Toronto coverage and actual rendering must be validated after configuration.
- Availability ranking uses the same immutable operator/City source receipts as its baseline. Score = rentable bikes / all valid mapped stations in each neighbourhood. No-station areas have an undefined denominator; missing/invalid/stale reports exclude that area. Rejected station coordinates exclude the whole ranking because their true spatial assignment is unknown. Equal ratios share ranks. Manual display bins [0,2), [2,5), [5,10), [10,infinity) are cartographic, not official service thresholds.
- Automatic acquisition preserves receipt times; reference cache reuse is explicitly marked. Historical snapshots are re-evaluated against present time, never treated as current. The UI shows the latest 50 snapshot IDs; older immutable rows remain in DuckDB.

## Toronto catalogue reference layers — added October 2026

- Green Spaces: https://open.toronto.ca/dataset/green-spaces/ . Replaces the deprecated Parks dataset (the City explicitly flags Parks as inaccurate). Generalized, non-exhaustive public/private open spaces; access is not guaranteed. Monthly catalogue cadence, not live conditions.
- Cycling Network: https://open.toronto.ca/dataset/cycling-network/ . Shared and dedicated cycling infrastructure; semiannual catalogue cadence. Infrastructure high/low attributes are source classifications, not inferred route safety. No routing or current-closure claim.
- Acquisition: `.venv/bin/python -m server.reference`. Fixed resource names; OGC:CRS84 verified explicitly; no geometry repair. Invalid geometries/types, duplicate identifiers and out-of-region coordinates are quarantined. Immutable raw responses and bundle archives are retained under `data/`; atomic named snapshots serve the UI. Metadata and resource SHA-256, retrieval time, source modification, cadence, licence metadata and rejection reasons are in each receipt. Missing licence metadata remains explicit.
- Map: green polygons and blue lines, qualitative categories; original geometries in longitude/latitude, Web Mercator display. Reference snapshots are separate from the observed-state replay and scenario inventory. They are refreshed only by the acquisition command, not the two-minute Bike Share cycle.
- Inspected but NOT integrated: Road Restrictions (https://open.toronto.ca/dataset/road-restrictions/), a separate live feed requiring temporal validation; TIN (https://open.toronto.ca/dataset/triangular-irregular-network-tin/), derived from 2023 LiDAR 2.5 m bare-earth data, horizontal EPSG:2952 and vertical CGVD2013. Terrain must be processed and datum-validated before display; no terrain elevation is currently inferred from it.

## Road restrictions and processed terrain — 2026-10-21

Road Restrictions uses the official v3 XML resource (`https://secure.toronto.ca/opendata/cart/road_restrictions/v3?format=xml&stream=n`). Full-file JSON validation failed on an invalid escape; strict CSV validation also failed on quoting. XML passed without source repair. Exact XML bytes and every success/failure bundle are archived under `data/roads/`. Start/end/update timestamps are epoch milliseconds; GeoPolyline is parsed as longitude/latitude, with an explicitly labelled source representative-point fallback when its extent cannot be validated. Date-window classification deliberately does NOT evaluate daily work schedules or assert active passability. Transport freshness is based on retrieval age (300 seconds); record amendment times remain separate. Source URL, hash, counts and errors are exposed. Latest roads are independent of Bike Share replay and cannot mutate scenarios.

Road acquisition runs through the existing 120-second process-local polling coordinator, shares Pause/Resume and manual refresh, never overlaps itself, and reports failed acquisitions as unavailable. The map polls the local snapshot every 15 seconds; inspection keeps the receipt associated with the selected feature. No road-routing action is enabled.

Terrain archive SHA-256: `268bf5094437d942ecca5e521368affa58623427a22ff1e4c4bcebbf9f4a1cb6`. Source PolygonZ PRJ verified equivalent to EPSG:2952; Z retained in metres CGVD2013 from catalogue metadata. 2,628,358 nondegenerate closed triangles accepted, zero rejected, vertex elevation range 65.175–224.294 m. Three sampled triangles were reconciled exactly against served vertex elevations. Spatial index is SQLite R-tree; original SHP/SHX/DBF remain authoritative. The API transforms XY only to longitude/latitude, retaining orthometric vertex elevations in explicit attributes rather than misleading GeoJSON ellipsoid Z. The viewport is bounded and capped at 4,000 triangles with visible truncation. Map colour is calculated mean of the three vertex elevations, fixed ramp 70/100/150/200/250 m; original Avg_Elev, Slope, Aspect, Ptg_Slope retained. The overlay is flat reference cartography, not integrated 3D terrain. No new DEM raster, interpolation, hydrologic conditioning, flood forecast or building-datum alignment is claimed.

The new Terrain 3D tab is distinct from the earlier flat elevation-coloured map overlay. It uses original 2023 TIN CGVD2013 elevations, or explicitly labelled sampled LODs, in a bounded local projected scene. It does not perform a vertical-datum conversion or imply photorealistic textures, live elevations, hydrologic validation, or citywide streaming.
