# Five-person site-history comprehension gate

Status: not conducted. Recruit five distinct people; do not substitute automated or simulated responses.

Use the completed local interface with real, qualified examples. Give each participant these tasks without first teaching the intended answers:
1. Select a site and identify the source and retrieval date of a planning record.
2. Compare two dates and explain what the changed publisher status establishes.
3. Explain what a record absent from a later complete export establishes.
4. Distinguish a candidate association from a confirmed link.
5. Explain baseline-only history and unavailable energy data.

Required interpretation: record/status changes and disappearance do not establish physical construction, demolition or completion; uncertainty and missing data remain unknown. Record the participant's own explanation, errors, and task outcome. Avoid collecting identifying details; use anonymous participant IDs.

A receipt must contain participant_id, date, tested_build, evidence_reference, task_results, passed, and human_participant=true. Each of the five task results must include the participant's response and passed=true. All receipts must refer to the same tested build. These fields validate receipt completeness; they cannot establish that a session actually occurred. Keep detailed responses locally, outside the public build. All five must pass. A failure requires a design correction and a fresh five-person passing evaluation; do not discard failed sessions to manufacture a pass.

This gate is in addition to source rights, identity, full accounting, match review, history, browser QA and public isolation. Passing it alone cannot authorize publication.
